`PUT /v1/forms/:id/destinations` and `POST /v1/forms` no longer silently store a Google Sheets or Salesforce destination that delivers into nothing. With an API key or an MCP connection, a new or changed enabled entry whose provider the workspace has not connected answers 400 `INTEGRATION_NOT_CONNECTED` with `integrationsUrl`, the absolute integrations page, and a message saying the entry is new or changed. Google Sheets counts as not connected on a deployment with no Google OAuth client, and the message then says the deployment cannot connect it. An entry the same as the stored one is kept, so an unrelated edit on a form whose connection was removed still saves: the comparison ignores the rows an editor keeps unfinished (`drafts`), reads `null` as absent, and treats a field written as one value or as a list of one as the same. A browser session is never refused, because the Connect tab saves a card switched on before its provider is connected. Every such entry, and a spreadsheet entry with no sheet yet, is listed in a new `warnings` field of the answer. Duplicating a form is unchanged: the copy stays in the same account, with the same connections.
