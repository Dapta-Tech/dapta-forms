Opening an old dashboard link no longer signs you out. When `PUBLIC_APP_URL` is set and a browser opens `/admin` (or anything under it) or `/onboarding` on a different hostname, for example an old domain that keeps serving after a domain move, the app answers a 302 to the same path and query on the `PUBLIC_APP_URL` origin before anything reads the session. Any GET or HEAD for `/api/auth/refresh` on another hostname hops the same way, so the refresh runs where the session cookie lives. Before, the old host had no session cookie (it is host-only), so the dashboard's 401 went to the refresh, the refresh went to the sign-out on `PUBLIC_APP_URL`, and the person was signed out there, upstream session included. The rules are the sign-in hop's (hostnames compared case-insensitively, read from the first `X-Forwarded-Host` entry, else `Host`; the target is always the configured origin). Public forms, embeds, `/embed.js`, file links, `/api/public/*`, static assets and images keep serving on every host; POSTs (Server Actions, form posts from tabs opened before the move) and page `fetch()` calls from such tabs are not redirected. On another hostname, sign-out now clears that host's cookie, lands on that host's sign-in page and skips the upstream revoke, which could end the session the `PUBLIC_APP_URL` host is signed in with. Without `PUBLIC_APP_URL`, or on its own host, nothing changes.
